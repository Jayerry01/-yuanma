# 《流星蝴蝶剑.net》输入轮询、按键缓冲队列与搓招识别系统逆向规范

> **二进制基准**: `Meteor.exe` (2002 原版，基址: `0x00400000`)  
> **代码来源**: `08_Input_Combo_Buffer.c`（经 Ghidra 12.1.4 真实反编译）  
> **核心函数定位**:
> - `0x00486270`: `InputSystem::PollDeviceState`（DirectInput 设备轮询与 Win32 消息同步）
> - `0x00486A80`: `InputSystem::ProcessKeyQueue`（循环环形按键事件队列推入与老化）
> - `0x00487830`: `InputSystem::GetInputSingleton`（输入管理器单例访问点）
> - `0x00488130`: `InputSystem::MatchComboSequence`（连招指令模式匹配器：如 `AA`, `↓↑A`, `←→A`）

---

## 一、 输入状态机与环形缓冲队列

在 `08_Input_Combo_Buffer.c` 中，输入子系统维持一个容量为 32 个槽位的环形事件缓冲区（Circular Event Buffer）：

```c
typedef struct {
    uint16_t keyCode;      /* 按键虚拟键码 (方向键 / 攻击 / 跳跃 / 防御) */
    uint16_t eventType;    /* 0 = KeyUp, 1 = KeyDown, 2 = KeyHold */
    uint32_t frameStamp;   /* 触发时的物理帧计数器 (用于时间窗口计算) */
} InputKeyRecord;
```

- **采样周期**: 随游戏主循环在 `0x00486270` 进行每帧 1 次的同步采样。
- **老化机制**: 超过容差时间窗口（通常为 12 帧，即 400ms）的历史按键记录在 `0x00486A80` 中被标记为过期并被环形头指针覆盖。

## 二、 搓招模式匹配逻辑 (`0x00488130`)

《流星蝴蝶剑》的核心招式触发依赖指令序列的时序状态匹配：

1. **按键编码映射**:
   - `KEY_UP` (前): `0x01`
   - `KEY_DOWN` (后): `0x02`
   - `KEY_LEFT` (左): `0x04`
   - `KEY_RIGHT` (右): `0x08`
   - `KEY_ATTACK` (轻击/A): `0x10`
   - `KEY_HEAVY` (重击/大绝): `0x20`
   - `KEY_JUMP` (跳): `0x40`
2. **时序序列匹配 (Sequence Matching)**:
   - 以经典招式“下上A”（`↓↑A`）为例：
     - 检测栈顶最近按键是否为 `KEY_ATTACK`；
     - 向前回溯历史记录，在 $[t - 8, t]$ 帧内寻找 `KEY_UP`；
     - 再向前回溯，在 $[t_{up} - 8, t_{up}]$ 帧内寻找 `KEY_DOWN`；
     - 若三者均在时间容差窗内连续满足且未插入非法冲突键，匹配成功。
3. **招式分发与动作覆盖**:
   - 匹配成功后，调用当前角色的动作控制器，将目标招式的 Pose ID（通过 `character.act` 映射）注入角色有限状态机。
   - 若角色当前处于不可打断的后摇动作，指令将被暂存在预输入寄存器（Buffer Register）中，在当前动作的 `CanCancel` 帧自动触发。

## 三、 离散键事件入口、四通道命令层与攻击命令落点（2026-10-28，字节级实锚）

### 1. 唯一离散键入口 `FUN_004CB820` (1,009 B, `RET 0x8`)
所有离散按键（含鼠标）只从这里进入：**先无条件发 `cmd 0x31`**（8 B `{key, pressed}`），
再按 keyCode 分派——`0x20–0x47` → 40 项跳表 `0x4CBC14`（字节索引 `0x4CBC40`）；
`0x49–0x54` → 12 项表 `0x4CBC68`（索引 `0x4CBC80`）；`0x1000/0x1200` 由 `CMP` 直判（攻击/跳跃动作码）。

### 2. 攻击分支（`0x1000`）——纯按下沿 + 双闸
`TEST EBX,EBX; JZ`（**释放不做任何事**）→ 闸1 slot111 `FUN_004D0D90`（`[this+0x10] && [this+0x34C]`）
→ 闸2 slot109 `FUN_004CE2D0`（`[this+0x348]->vtable[21]()`）→ 载荷 slot37（实体句柄）→ `PUSH 0x1D`。
函数内唯一字符串 `"Active Attack"`（`0x5C9C34` → GameApp slot 172），仅此分支引用。
跳跃（`0x1200`）**不对称**：按下 slot67→slot31，释放也处理（`CALL [EDX+0x104]`）。

### 3. 四通道事件记录器（非状态快照）
| cmd | 载荷 | GameApp 槽 | 队列方法 | 落队列（280 B 移动组件, vfptr `0x5AA660`） |
|---|---|---|---|---|
| `0x31` | 8 B {key,pressed} | 220 | 10 | 12 B @+0x18 |
| `0x32` | 12 B 摇杆 A | 221 | 11 | 12 B @+0x48 |
| `0x34` | 12 B 摇杆 B | 222 | 12 | 16 B @+0x38 |
| `0x33` | 16 B {fwd,right,cnt,x} | 223 | 13 | 8 B @+0x28 |

四类各进各队列，由 per-frame tick（slot 19）统一排空。**方向缓冲 `this+0x2E8` 有两个写者**
（tick 轴驱动 `'f'/'b'/'l'/'r'` + 键事件 `FUN_004CBCE0` 经 vtable slot 24、字符走栈参数
`MOV [ECX],BL @0x4CBD41`）——克隆必须做**跨写者去重**。

### 4. `cmd 0x1D` 落点链（2026-10-28 第三跳 + 身份撞车裁定）
- `0x5A9FE0 + 0x7C` = `FUN_004BC710`（402 B）：懒建 `[0x5E0328]`（0x33C，ctor `0x44D020`——**与键位轮询器 `FUN_00503020` 共用同一设置实例**）
  → 快照 `FUN_0045A450`（`rep movsd`×5、字段至 +0xE8、`+0xEC` 起 0x1A dword）→ 门 `cfg+0xC8` 非零 → `FUN_004F1960(this)`。
- `FUN_004F1960`（15 B）：`this->vtable[17] (+0x44)` → 尾跳 `[返回值+0x1B4]`。尾跳编码为 `FF A2 B4 01 00 00`（disp32；disp8 形式 `FF 62 B4` 装不下该位移）。
- `FUN_004F1D90`（119 B，vtable[17]）：`PUSH 0x528` + `CALL 0x4CABD0` 懒建 PlayerController（0x5AA6A8 类，1,320 B），缓存于 `[宿主+0x1A4]`，建后 `CALL [vtd+0x10]` 通知宿主。
- `pc->vtable[109] (+0x1B4)` = `FUN_004CE2D0`（18 B）= `[pc+0x348] ? [pc+0x348]->vtable[21] : 0`。
- **身份撞车已裁定（同日复核）**：终端 `FUN_004CE2D0` 与按键闸2（`0x4CBBC6`）是同一函数——虚表归属扫描证实 `FUN_004CB820`（键事件入口）= `0x5AA6A8` 类 **slot 105**（数据引用 `0x5AA84C`；正典基读法 slot 125），而 `FUN_004F1D90` 懒建的产品正是同类单例。∴ 闸2 与终端是**同一对象上的同一武器侧闸**，分别在按键时刻与命令排空时刻求值 = **设计上的再判**（命令经事件队列，排空时状态可能已变——双闸查两次是刻意的）。
- `+0x348` = **武器控制器指针**：EquipWeapon `0x4CFD20` @`0x4CFD54` 安装、`0x4CB0B9` 清除；终端 `[pc+0x348]->vtable[21]` 即武器侧放行闸。偏移陷阱第五例：另一类在 `0x4E8437/0x4E8443` 以 `mov dword [edi+0x348],0/1` 把同偏移当布尔写。

### 5. 槽位正典与移植端三条硬要求
- 槽位正典基 = `0x5AA658`（PlayerController，150 方法）：`FUN_004CF5B0` = slot 86（+0x158）、
  `FUN_004CF540` = slot 85（+0x154）、`FUN_004CE100` = slot 65（+0x104，力竭滑落）；
  移动组件子对象虚表 `0x5AA6A8` 对同一段 run 以 **−18 槽** 重索引。引用槽位必须写
  `base + index` 加解析后地址（方法论第 10 条）。
- **攻击 = 带双闸的沿事件**（按帧采样鼠标按下必双发）；**攻击无释放路径、跳跃必有**（原版不对称）；
  **方向缓冲按 {tick, 键沿} 双源去重**，且是带 capacity 的可增长字节数组。

### 5. 武器能力探针：`vtable[21]` 是编译期常量（第四跳，2026-10-28）
- 武器控制器为 **Meyers 单例**：工厂 `FUN_004E3D80`（79 B，12 路跳表 `0x4E3DD0` → 12 个 51 B getter）。
  getter 模式 = 静态守卫 `[0x666414]` + ctor + `atexit(析构)` + 返回静态实例。
  `[pc+0x348]` 指向**静态实例**（如剑 = `0x666640`），非堆对象。
- 12 类 `vtable[21]` 仅两种实现（逐类机械重建，含 ctor/vtable 地址）：

  | 类型 | ctor | vtable | 槽 21 |
  |---|---|---|---|
  | 0 剑 | `0x4DD170` | `0x5AAB00` | `0x4F5860` = `MOV EAX,1; RET` |
  | 1 | `0x4E05C0` | `0x5AAE10` | `0x4F5860` = RET 1 |
  | **2** | `0x4DE770` | `0x5AAC50` | `0x4E40D0` = `XOR EAX,EAX; RET` |
  | **3** | `0x4DEF90` | `0x5AACC0` | `0x4E40D0` = RET 0 |
  | 4 | `0x4DFE80` | `0x5AADA0` | `0x4F5860` = RET 1 |
  | 5 | `0x4DE020` | `0x5AABE0` | `0x4F5860` = RET 1 |
  | **6** | `0x4DF730` | `0x5AAD30` | `0x4E40D0` = RET 0 |
  | 7 | `0x4DD8C0` | `0x5AAB70` | `0x4F5860` = RET 1 |
  | 8 | `0x4E0CD0` | `0x5AAE80` | `0x4F5860` = RET 1 |
  | 9 | `0x4E1420` | `0x5AAEF0` | `0x4F5860` = RET 1 |
  | 10 | `0x4E3530` | `0x5AAFE8` | `0x4F5860` = RET 1 |
  | 11 | `0x4E2CB0` | `0x5AAF70` | `0x4F5860` = RET 1 |

- **结论**：`weapon->vtable[21]` 是**编译期能力常量**，不是谓词——攻击命令不承担选招；
  对剑，cmd 0x1D 整链净效果 `return 1`。性质是**权限探询**（键路由在两道闸之间发出，随后上报
  `"Active Attack"`）。类型 2/3/6 返回 0 的语义**未命名**（不可推断"禁用"——若为非玩家武器则含义不同）。
- 槽 22 = `0x4E4070`（空 `RET 0x4`）。
- **待重测唯一项**：slot 40 = `FUN_004CFF40`（674 B，"Active Attack" 报告器）——"日志路径"分类
  仅凭字符串，按方法论需重测。
- 方法论：邻接猜构造器地址失败一次（应从 getter 的 CALL 目标控制流提取）。

### 6. `slot 40` = 攻击执行器（第五跳，2026-10-28）
`FUN_004CFF40`（674 B，**0x5AA6A8 基 slot 40**——`mem[0x5AA748]` 直读；0x5AA660 基同槽是
另一个也算实体句柄的 `FUN_004CFC00`，偏移陷阱第六例）：

- **状态筛**：slot 76 取状态值 → `CMP {1,0,3,6}` 放行，其余 `return 0`；`0xB` → slot 62 后 return 0。
- **武器闸**：`mov ecx,[esi+0x348]`（武器单例）→ `call [eax+0x20]`（武器 vtable[8]），为 0 走另一支。
- 建 3–4 个栈临时对象（`0x4024A0`、一个 vtable `0x5A94E4` 的 functor）后发双命令：
  - `PUSH 0x30 @0x4D0051` → `cmd 0x30` → slot 16 `FUN_004CFCA0`（56 B）：**清零 `+0x390/+0x394/+0x398`
    （含 `jumpForceY`）**——攻击先取消垂直冲量——再调实体 `vtable[32]`（4 参，`RET 0xC`）；
  - `PUSH 0x35 @0x4D00C3` → `cmd 0x35` → slot 18 `FUN_004D03F0`（**166 B，未读尾**）。
- 末尾 `MOV [ESI+0x524],EDX`。
- **归属勘误**：`"Active Attack"` 不在本函数（体内 0 引用；数据引用仅 CRT 分配器
  `0x5D59E8/0x5D59A4`）——它在**调用方** `FUN_004CB820` @`0x4CBFB`，且以 slot 40 的返回值
  为条件（`TEST/JZ`，返回 0 则跳过上报）：**通知报的是"执行器运行了"，不是"键按下了"**。

### 7. 攻击按下 = 双路径（修正后的架构）
| 路径 | 性质 | 终止于 |
|---|---|---|
| `cmd 0x1D` | 权限探询 | 武器能力常量（9 类 1 / 3 类 0） |
| slot 40 | **执行器** | `cmd 0x30`（清 jumpForceY）+ `cmd 0x35` → `FUN_004D03F0`（未读） |

`"Active Attack"` 通知以执行器返回值为条件挂在两条路径之上。**未读尾**：`FUN_004D03F0`（166 B）。

### 7. `FUN_004D03F0`（166 B）：攻击执行终端——禁跳、第三计时器、动作派发（第六跳）
- **状态筛**：slot 76 取状态 → `CMP 7 / CMP 9` 命中即拒（0x4D0490：`XOR EAX,EAX; POP ESI; RET 0x10` 返回 0）。
- **`slot 29 (+0x74)` @0x4D0422**：全链唯一接收调用方动作载荷的调用（4 参）——**动作执行本体（未读）**。
- **`SetState(4)`**：slot 75 写 `[pc+0xDC]=4` → 跳跃派发器（`FUN_004CF5B0`）12 项索引表 `0x4CF75C`
  的字节 4 = case 3 = `OR EAX,-1; RET`（no-op）——**攻击与跳跃互斥由存储状态实现，非标志位检查**；
  复位 `0x4CB0A7` 恢复。∴ 攻击按下后跳跃派发器整段失效，直到状态被写回。
- **第三计时器 `[pc+0x210]`**（`FUN_00549A90`，103 B）——与 +0xE8（持跳）、+0xF0（次级）并列；
  三个计时器互不共用，移植不可合并。
- **冲量向量保存**：`[+0x390..+0x398]` → `[+0x3B8..+0x3C0]`——挺过 cmd 0x30 的清零（上一跳）。
- **重发 `cmd 0x35`**（双空参 + `CALL [EAX+0xC]`）→ 新状态重入派发。成功返回 1（0x4D0487），拒绝返回 0。
- **移植端语义链**：攻击按下 → 执行动作（slot 29，待读）→ 禁跳（状态 4）→ 起攻击计时器 → 存冲量 → 重入派发。
